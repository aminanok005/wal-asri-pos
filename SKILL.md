# Cafe POS Ecosystem - Vibe Coding Skill (SKILL.md)

This skill specification defines the automated workflow, architectural constraints, CLI tooling requirements, and coding standards for AI Coding Assistants (Cursor, Claude, Copilot) working in the **Cafe POS Monorepo**.

---

## 1. System Architecture Context

The Cafe POS System is an **Offline-First Cross-Platform Ecosystem**:
- **POS Desktop / Terminal**: Tauri 2 (React + TypeScript + Encrypted SQLite via SQLCipher)
- **Mobile Order / Tablet**: Expo (React Native) + TanStack Query
- **Admin Monitor WebApp**: Next.js (App Router) + Tailwind CSS
- **Backend**: Golang (Grit Framework) - Modular Monolith on PostgreSQL + Redis
- **Monorepo Manager**: `Bun` native workspaces (`>= 1.3.14`)
- **API Contracts**: OpenAPI 3.0 (`/contracts/openapi.yaml`) -> Generated TypeScript Types

---

## 2. Core Architectural Constraints & Invariants

All code generated by AI Agents MUST strictly adhere to these rules:

### 2.1 Strict Money Rule (Integer Minor Units)
- **NEVER** use `float32` or `float64` for money calculation.
- All monetary values must be stored and transmitted as **Integer Satang** (e.g., ฿45.50 = `4550` satang).
- **TypeScript**: Wrap minor units in a pure domain `Money` Value Object.
- **Go**: Use `int64` minor units or `shopspring/decimal`.

### 2.2 Offline-First Transactional Outbox
- The POS terminal MUST complete checkout, record sales, and print receipts without network access.
- Local SQLite write operations MUST execute in an atomic transaction:
  ```sql
  BEGIN TRANSACTION;
  INSERT INTO orders (id, total_satang, status, created_at) VALUES (...);
  INSERT INTO outbox_events (id, event_type, payload, idempotency_key, synced) VALUES (...);
  COMMIT;
  ```
- All client-generated primary keys MUST be **UUIDv7** (sortable, collision-free offline IDs).
- Sync Engine drains the `outbox_events` table to Go server's `/sync/push` with exponential backoff & idempotency verification.

### 2.3 Layer & Domain Boundaries
- **Client Domain (`src/features/{feature}/domain/`)**: Pure TypeScript business rules. No React, no Tauri, no SQL imports.
- **Server Domain (`internal/{feature}/domain/`)**: Authoritative Go domain logic. Re-validates all client data on ingest.
- **Rust Core (`src-tauri/src/`)**: Pure native hardware adapter (ESC/POS USB/Bluetooth printing, cash drawer, SQLCipher key, native SQLite worker). Contains NO business rules.

### 3.5 Monorepo orchestration — Bun workspace filtering

There is no `turbo.json` and no `pnpm-workspace.yaml`. The root `package.json`
declares `"workspaces"` and holds the root scripts.

```bash
bun install                                    # install across all workspaces
bun run --filter <name> <script>              # run a script in one workspace
bun run --filter '*' <script>                 # run across all workspaces
bun add --filter <name> <pkg>                 # add a dep to one workspace
bun add -D -w <pkg>                           # add a root devDependency
bunx <tool>                                   # one-off binary (e.g. bunx tsc)
```

Or orchestrate via root scripts:

```json
"scripts": {
  "generate:types": "openapi-typescript contracts/openapi.yaml -o packages/api-types/src/index.ts",
  "build": "bun run --filter '*' build",
  "typecheck": "bun run --filter '*' typecheck"
}
```

> ⚠️ **Pin Bun to avoid a lockfile-version trap.** Bun `1.4+` writes `bun.lock`
> with `lockfileVersion: 2`; tooling that expects v1 (the format Bun `1.3.x`
> produces) can fail to parse it and silently lose the workspace graph.
> Declare `"packageManager": "bun@1.3.14"` and avoid unattended Bun auto-updates.

## 4. Vibe Coding Standard Operating Procedure (SOP)

When assigned a feature task or vertical slice, execute steps in this exact order:

```
[1. Contract (openapi.yaml)] ──► [2. Generate TS Types] ──► [3. Grit Backend Generator]
                                                                     │
[5. UI Presentation & Outbox] ◄── [4. SQLite Client Schema] ◄────────┘
```

1. **Step 1 — Contract**: Edit `/contracts/openapi.yaml` to define request/response schemas.
2. **Step 2 — Generate Types**: Run `bun run generate:types` (`openapi-typescript contracts/openapi.yaml -o packages/api-types/src/index.ts`).
3. **Step 3 — Grit Backend Slice**: ⛔ **BLOCKED** pending §3.4. Once unblocked:
   - Run `grit generate resource <module_name>` inside `/services/api-backend`.
   - Write SQL queries in `/services/api-backend/db/queries/<module>.sql` and run `sqlc generate`.
4. **Step 4 — Client Local Storage**: Define local SQLite tables and migrations in `apps/pos-desktop/src-tauri/migrations/`.
5. **Step 5 — React/Tauri Slice**: Create local Zustand store + TanStack Query hooks + SQLite Outbox transaction.

## 5. Verification & Quality Gates

Before declaring a task completed:
- [ ] No `float` types found in money calculations.
- [ ] Local checkout works with simulated offline network (airplane mode).
- [ ] All outbox events use UUIDv7 idempotency keys.
- [ ] `bunx tsc --noEmit` and `go test ./...` pass with zero errors.

> **Bun command notes.** Bun does not resolve binaries from `node_modules/.bin`
> the way pnpm does. Use `bunx <tool>` for one-off binaries (`bunx tsc`) and
> `bun run <script>` for package scripts. `bun tsc` is **not** valid.
> Recursive and filtered runs use Bun filters, not `pnpm -r`:
> `bun run --filter '*' <script>`, `bun run --filter <name> <script>`.
